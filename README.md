# Каталог товаров на React

Учебное React-приложение для контрольной точки по дисциплине «Фреймворки JavaScript». Приложение получает товары из Fake Store API, показывает каталог и отдельную страницу выбранного товара.

## Технологии

- React и функциональные компоненты;
- хуки `useState` и `useEffect`;
- React Router DOM;
- Fetch API;
- CSS Grid и адаптивные стили;
- Vite;
- `gh-pages` для публикации.

## Структура проекта

```text
public/
└── 404.html                  # восстановление SPA-маршрута на GitHub Pages
src/
├── components/
│   ├── ProductCard.jsx       # карточка товара в каталоге
│   └── Rating.jsx            # переиспользуемые пять звёзд
├── pages/
│   ├── ProductsPage.jsx      # список товаров
│   ├── ProductPage.jsx       # страница выбранного товара
│   └── NotFoundPage.jsx      # неизвестный маршрут
├── App.jsx                   # таблица маршрутов
├── main.jsx                  # точка входа и BrowserRouter
└── index.css                 # стили приложения
index.html                    # HTML-шаблон и восстановление SPA-маршрута
vite.config.js                # Vite и базовый путь публикации
```

## Страницы и маршруты

- `/products` — каталог всех товаров. На широком экране карточки расположены по три в строке.
- `/product/:id` — подробности конкретного товара: название, изображение, цена, описание и рейтинг.
- любой неизвестный адрес — страница «404 — Страница не найдена».
- `/` автоматически перенаправляет на `/products`.

Кнопка «НАЗАД» использует `navigate(-1)`, поэтому возвращает именно на предыдущую страницу в истории браузера. Если товар с указанным `id` не существует, показывается отдельное сообщение «Товар не найден».

## API и состояния страницы

Данные загружаются через `fetch`:

```text
https://fakestoreapi.com/products
https://fakestoreapi.com/products/{id}
```

Запросы выполняются внутри `useEffect`, результаты сохраняются через `useState`. Проверяется `response.ok`; отдельно отображаются загрузка, ошибка и успешный результат. `AbortController` отменяет запрос при размонтировании компонента и не позволяет устаревшему запросу изменить состояние.

## Компонент Rating

Один компонент `Rating` используется и в каталоге, и на странице товара. Он получает дробное значение через prop `rate`, округляет его с помощью `Math.round(rate)` и всегда выводит пять звёзд. Заполненные звёзды золотые, незаполненные — тёмно-серые.

Примеры округления: `3.4 → 3`, `3.5 → 4`, `4.8 → 5` заполненных звёзд.

## Установка и запуск

Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

После запуска Vite выведет локальный адрес. Команда `npm start` также запускает режим разработки.

## Сборка

```bash
npm run build
npm run preview
```

Готовая сборка помещается в каталог `dist`.

## Публикация на GitHub Pages

Сначала создайте репозиторий GitHub и свяжите его с проектом:

```bash
git init
git add .
git commit -m "Create React products catalog"
git branch -M main
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

Перед публикацией укажите реальное имя репозитория в базовом пути. Не заменяйте `REPOSITORY` вымышленным значением:

```bash
VITE_BASE_PATH=/REPOSITORY/ npm run deploy
```

Команда `predeploy` автоматически выполнит сборку, а `gh-pages` отправит содержимое `dist` в ветку `gh-pages`. В настройках GitHub откройте **Settings → Pages** и, если это не произошло автоматически, выберите публикацию из ветки `gh-pages`, каталог `/ (root)`.

Адрес project page будет иметь вид:

```text
https://USERNAME.github.io/REPOSITORY/
```

### Почему прямые ссылки работают на GitHub Pages

Используется `BrowserRouter` с `basename`, полученным из `VITE_BASE_PATH`, поэтому адреса остаются чистыми: `/REPOSITORY/products` и `/REPOSITORY/product/1`, без символа `#`.

GitHub Pages не умеет самостоятельно отдавать `index.html` для неизвестного SPA-маршрута. Файл `public/404.html` сохраняет маршрут в query-параметре и перенаправляет на корень приложения, а скрипт в `index.html` восстанавливает исходный адрес до запуска React. Поэтому обновление вложенной страницы продолжает работать.

Если публикуется корневой пользовательский сайт `USERNAME.github.io`, а не project page, используйте `VITE_BASE_PATH=/` и измените в `public/404.html` значение `segmentsToKeep` на `0`.

## Что рассказать на защите

1. `App.jsx` содержит `Routes`: каталог, товар по динамическому `id`, перенаправление с корня и маршрут `*`.
2. `ProductsPage` загружает массив товаров в `useEffect`, хранит его в `useState` и выводит карточки через `map` с `key={product.id}`.
3. `ProductCard` получает товар через props, а `Link` формирует адрес `/product/{id}`.
4. `ProductPage` получает `id` через `useParams`, загружает один товар и возвращается назад через `useNavigate`.
5. `Rating` округляет число функцией `Math.round` и переиспользуется на обеих страницах.
6. У запросов есть состояния загрузки и ошибки, а `AbortController` выполняет очистку.
7. CSS Grid создаёт три колонки и медиазапросами сокращает их число на узких экранах.
